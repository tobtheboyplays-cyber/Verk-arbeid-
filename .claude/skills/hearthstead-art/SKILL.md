# Hearthstead art & animation pipeline

Every pixel and every keyframe in Hearthstead is **generated by code in
`hearthstead-neoforge/tools/`** — never hand-painted, never downloaded. That
is what makes the assets original by construction, exactly sized, diffable in
git, and reproducible from a clean checkout. Regenerating must always be
idempotent: run the generator twice, get identical bytes.

Theme is fixed: **grounded European medieval** (linen, oak, iron, wool,
burgundy, forest green, amber firelight). No fantasy neon, no modern shapes.

## Environment toolchain

| tool | state | use |
|---|---|---|
| Python 3.11 + Pillow | preinstalled | all texture/GUI/preview generation |
| numpy | `pip install numpy` (done) | signal work in `gen_sounds.py` |
| ImageMagick (`convert`, `import`) | `apt-get install -y imagemagick` (done) | screenshot capture, image inspection |
| x11-apps (`xwd`), xdotool | `apt-get install -y x11-apps xdotool` (done) | window capture fallback for client boot |
| ffmpeg | preinstalled | audio encode (OGG), animation preview reels |
| Xvfb + Mesa llvmpipe | preinstalled | real client boot headless (`qa/scripts/client_boot.sh`) |
| Blender | **NOT installed** and not needed | Minecraft entity art is boxy UV-mapped geometry; `SettlerModel` + `preview_settler.py` covers it. Only pursue Blender if a genuinely non-box mesh is ever required. |

Install anything missing with `apt-get install -y -q <pkg>` / `pip install`;
outbound traffic goes through the preconfigured proxy and works.

## The generators (`hearthstead-neoforge/tools/`)

| script | produces | notes |
|---|---|---|
| `texlib.py` | shared palette + pixel helpers | `PALETTES` (dark→light 5-stop ramps), `box_faces`, `shade`, `cloth`, `FACE_LIGHT`. **Light convention: top-left key — top brightest, front neutral, sides dimmed, back/bottom darkest.** All other generators import this; add new colours here, not locally. |
| `gen_settler.py` | settler entity skins (128×64) | `UV` table **must mirror `SettlerModel.createBodyLayer()`** exactly; `PROFILES` defines each profession's cloth/hair/skin/headgear. |
| `gen_blocks_items.py` | block + item textures | hearth, writs, handbook |
| `gen_gui.py` | GUI sheets | dark iron-and-oak panel language from the user's reference image |
| `gen_sounds.py` | OGG sounds + voices | synthesized, no samples |
| `gen_structures.py` | structure NBT | **1.21: DataVersion 3955, output dir `structure/` (singular)** |
| `preview_settler.py` | orthographic turnarounds | composites skins onto model geometry (front/side/back) — the only honest way to review entity art headlessly |
| `anim_check.py` | animation QA | static parse of `SettlerAnimations.java` |
| `validate_assets.py` | full asset validation | currently 144/144; knows the 1.21 layout |

Run a generator, then always re-run the validator:

```bash
cd hearthstead-neoforge
python3 tools/gen_settler.py && python3 tools/validate_assets.py
```

## Keyframe animation

Animations live in `client/model/SettlerAnimations.java` as vanilla
`AnimationDefinition`s and are played from `SettlerModel.setupAnim` based on
the entity's synced `SettlerActivity`.

**Standing product rule (user directive): every task has its own animation.**
A new settler task is not done until it has a bespoke clip — reusing a
neighbouring task's clip is a placeholder, not a feature. Reference bar is
TekTopia, and the explicit instruction is to beat it.

Rules that keep clips readable in-game:
- Bone names must match `SettlerModel` parts exactly (`root`, `torso`, `head`,
  `right_arm`, `left_arm`, `right_leg`, `left_leg`, `cloak`).
- Looping clips must close: first and last keyframe of every channel equal.
- `CATMULLROM` for flowing motion; `LINEAR` for an impact frame (a strike
  must snap, not ease).
- Amplitudes stay in vanilla range — over-rotation reads as broken, not lively.
- Every clip needs a distinct silhouette and rhythm: the activity should be
  recognisable from across the village with no nameplate.
- **Sound-sync contract**: the impact keyframe's timestamp must match the tick
  the goal plays its sound (e.g. `CHOP` strikes at t=0.55s of a 1s loop;
  `LumbererWorkGoal` plays the thock at tick 11 of a 20-tick cycle). Encode
  the contract in a comment above the clip and assert it in `anim_check.py`.

Verify with:

```bash
python3 tools/anim_check.py          # loop closure, ordering, amplitude, sync
tools/hearthstead-qa animation       # same, through the QA controller
```

## Verification is not optional

Art and animation changes run through the QA controller like everything else
(see the `hearthstead-qa` skill and `qa/PROTOCOL.md`):

- `tools/hearthstead-qa validate` — asset layout/reference integrity
- `tools/hearthstead-qa animation` — keyframe QA
- `tools/hearthstead-qa client` — real client boot under Xvfb + screenshot
- `tools/hearthstead-qa visual` — screenshot gate; **a UI/art claim without a
  screenshot actually inspected is BLOCKED, never PASS**

Previews are evidence: regenerate `preview_settler.py` turnarounds after any
skin change and look at them before claiming the art is good.

## Adding a new profession (worked example)

1. `gen_settler.py`: add a `PROFILES` entry (cloth, trim, hair, skin, headgear).
2. Regenerate skins; check the turnaround preview renders correctly.
3. `gen_blocks_items.py`: add the profession's writ/tool item art.
4. `SettlerAnimations.java`: author its work clip(s) — one per distinct task.
5. Wire the clip in `SettlerModel.setupAnim` off the activity enum.
6. `gen_sounds.py`: add work sounds; match the impact keyframe timing.
7. `en_us.json` (+ `nb_no.json` at release): names, tooltips, messages.
8. `validate_assets.py` + `anim_check.py` green, then a full QA run.
