# Hearthstead art & animation pipeline

Every pixel and every keyframe in Hearthstead is **generated by code in
`hearthstead-neoforge/tools/`** — never hand-painted, never downloaded. That
makes the assets original by construction, exactly sized, diffable in git,
and reproducible from a clean checkout. Regeneration is idempotent: run a
generator twice, get identical bytes (explicit integer seeds only — never
Python's salted `hash()`; use `zlib.crc32(key.encode())` like `gen_settler`).

Theme is fixed: **grounded European medieval** (linen, oak, iron, wool,
burgundy, forest green, amber firelight). No fantasy neon, no modern shapes.
Because pixels are placed by Python, every craft rule below is written so a
code generator can follow it and a reviewer can check it — from the PNG or
the code, without taste debates.

## Environment toolchain

Python 3.11 + Pillow (all texture/GUI/preview generation), numpy
(`gen_sounds.py`), ImageMagick/xdotool/x11-apps (screenshots, inspection),
ffmpeg (OGG encode, preview reels), Xvfb + Mesa llvmpipe (headless client
boot via `qa/scripts/client_boot.sh`) — all installed. Blender is NOT
installed and not needed: boxy UV geometry is covered by `SettlerModel` +
`preview_settler.py`.

## Palette & ramp law (numbers, not vibes)

Every material is a **5-stop ramp, index 0 = darkest → 4 = lightest**, defined
in `texlib.PALETTES`. Rules for any ramp you add or retune:

1. **Value span**: total ramp spans ≥ 28 HSV-V points (of 100); adjacent
   stops differ by 7–12 V. Below 7 the step is invisible at 16px; above ~15
   the ramp reads as separate materials. Never start at V<12 or end at V>96
   (pure black/white are reserved for ink and glints).
2. **Hue shift**: highlights drift **warm** (toward yellow, hue +8° to +15°
   across the ramp for warm materials), shadows drift **cool** (−10° to −20°
   toward blue/violet for cool materials like iron and stone). A ramp whose
   five stops share one hue is a *flat-shading smell* (see failure smells).
   House exemplar: `ember` H9→H38 (+29° dark→light); `amber` (+11°) passes.
   Older value-only ramps (`burgundy` H356 flat, `iron` H240 flat) are
   grandfathered — match the rule when you next touch them.
3. **Chroma curve**: saturation peaks at stops 1–2 (the dark midtone), not at
   the ends: shadow stop ≈ 0.7–0.9 × peak S, lightest stop ≈ 0.4–0.7 × peak.
   Never exceed S 90 anywhere (medieval cloth is dyed, not neon).
4. **Skin exception**: skin ramps stay inside a ±10° hue band around
   H24–H28, shadows go warm (toward red-brown), **never** toward blue or
   gray — blue-shadowed skin reads as sickness.
5. **Shading = stepping the ramp.** Model a form by choosing ramp indices.
   `shade(c, f)` multiplies RGB uniformly (a pure value shift, no hue shift):
   it is reserved for (a) `FACE_LIGHT` directional lighting, (b) micro
   accents within ±12% (`0.88 ≤ f ≤ 1.12`). Building a whole gradient out of
   `shade()` factors is the number-one generated-texture defect.
6. **Colour budget**: a 16×16 texture uses one, at most two ramps plus ≤2
   accent pixels; a settler layer uses the ramps its `PROFILES`/outfit entry
   names and nothing else. More ramps = mud at distance.

**Light convention (unchanged, absolute): top-left key.**
`FACE_LIGHT = top 1.14, front 1.0, sides 0.90, back 0.82, bottom 0.62`.
On any single face, the lit accents sit up-and-left, the shadow accents
down-and-right (the `rivet()` crown at `(cx−1, cy−1)` with a shadow crescent
only on the down-right rim is the reference — a full shadow ring reads as a
hole). Block MATERIAL textures for real-geometry models carry **micro-relief
only** — every groove gets its own 1px lit edge (up/left) and shadow edge
(down/right) — and **no macro gradient**, because Minecraft's own per-face
shading supplies the large-scale light (see `gen_plaque.py` header).

## Cluster doctrine — the cardinal sins

Pixel art is made of **clusters**: contiguous same-colour shapes. Good
texture is a few well-shaped clusters repeated with *varied distribution*;
bad texture is either per-pixel static or mechanical bands.

- **Banding** (sin #1): two parallel runs of the same shape in consecutive
  ramp steps hugging each other or an edge — a 1px pseudo-gradient that
  blurs the form. Detectable: row j and row j+1 have the same run pattern
  shifted 0px, in adjacent ramp indices, for ≥4px. Includes *staircase
  banding* (each diagonal step carries an identical shade pixel at the same
  offset) and *outline hugging* (a full inner highlight tracing the
  outline). Fix: vary cluster lengths, drop the middle band, or merge steps.
- **Pillow shading** (sin #2): ramp indices arranged in concentric rings
  around the shape's centre, as if the viewer were the light. Detectable:
  the brightest cluster's centroid is not up-left of the darkest cluster's
  centroid. Every free-standing form must pass the *centroid test*: mean
  position of stop-4 pixels sits above/left of mean position of stop-0/1.
- **Orphan pixels** (sin #3): single pixels touching no same-colour
  neighbour (8-connected). Allowed only as deliberate glints — rivet crowns,
  hair glints, eye catch-lights — at most 1 per 8×8 region, ≥3px apart.
  Everything else clusters in runs of 2–4.
- **Noise-as-texture** (sin #4): independent per-pixel randomness is TV
  static, not weave. Flip probability ≤25% per pixel, flips move **one ramp
  step** (rarely two), and the result must still show cluster runs.
  `texlib.woven` (16% down / 6% up) is the calibrated house weave.
- **Dithering** at 16px: checkerboard between **adjacent** stops only, on
  ≤25% of a surface, only for rough matte materials (parchment fibre, flour
  dust, stone weathering). **Never** on skin, metal, eyes, or anything that
  animates. If a transition needs more than one dither band at this size,
  the ramp step is too large — fix the ramp instead.
- **Anti-aliasing**: none. Hard texel edges are the Minecraft idiom.
- **Outlines / sel-out**: only items and GUI sprites on transparent
  backgrounds get outlines — in the object's **own ramp stop 0** (never pure
  black), lightened 1–2 stops along the top-left where light hits (selective
  outline). Tiling block faces and entity-skin interiors get **no** outlines;
  parts separate by value contrast, not by drawn lines.

## Material recipes (code-followable)

Each recipe names the ramp, the value distribution, and the placement rules
a generator must satisfy.

- **Iron / forged metal** (`iron`, `iron_forged`): the *highest-contrast*
  material — full 5-stop span inside a few pixels. 60–70% of the surface
  sits in stops 0–1; the specular is a **single 1px line or dot of stop 4**
  placed 1px inside the top-left edge of the form, ≤10% of the surface.
  Reflective curves read as **dark–light–dark bands** across the reflection
  axis; bands on differently-oriented faces must not be parallel. Forge
  texture = sparse peen dashes (stop 0/1, 1–2px) each with a stop-3 lit
  edge up-left. Polished caps (rivet crowns) may take one `bone[4]` glint
  pixel — the pixel that stops iron reading as a dark smudge at distance.
  No dithering on metal, ever.
- **Brass** (`brass`): like iron but warmer and quieter — catch-light on
  upper-left rims only, **patina** (desaturated stop 0) pooled in recesses
  and hollows; staggered planished dimples on large surfaces. Keep it
  "restrained aged", never gold-bling.
- **Wood** (`oak`, `oak_light`, `oak_carved`): body in stops 2–3. Grain =
  1px streaks of stop 0–1 running **along the board axis**, spaced 3–7px
  irregularly, each streak broken (jogging or ending every ≤6px so no line
  runs the full length). Board seams = stop 0; the row just after a seam
  gets a ×1.08 catch-light. Knots: ≤1 per 12×12 region, large surfaces
  only. End grain is different: short strokes **across** the thickness
  (`endgrain_oak`) — rotate the UV rather than repaint. Grain and board
  axis must never disagree — the most legible wood error there is.
- **Cloth / linen / wool** (`linen*`, `wool_gray`, `burgundy`, `forest`,
  `wheat`): the *softest* material — adjacent-step transitions only; a
  boundary that jumps two ramp steps reads as painted metal. Base at stop 3
  with the house weave; wool uses effectively 3 values (2–4). Structure
  beats noise: one shoulder catch-light row (stop 4 ×1.05), one fold crease
  (stop 1 ×0.88) where the garment bunches (above belt, behind knee, inside
  elbow), hem/trim in its own ramp. Folds are 1px lines perpendicular to
  the stretch — each fold a tiny cylinder: lit above, dark in the crease.
- **Leather** (`leather`): mid contrast — 3–4 of the 5 stops. Sheen is a
  single 2–3px band of stop 4 on the highest curve, no white glint. **Worn
  edges**: a stop-4 1px run along edges that rub (belt top edge, strap
  edges, apron hem corners), plus 1–2 sparse stop-1 scuff nicks. Straps get
  a stop-0 seam line where they cross cloth.
- **Stone** (`stone`): irregular courses (`texlib.stone`), mortar = stop 0
  ×0.85, per-stone base picked from stops 1–3 with ±6–12% value variance,
  top row of each stone ×1.12 catch-light, penultimate row ×0.9. Courses
  offset so vertical joints never align. Weathering dither allowed, ≤25%.
- **Parchment** (`parchment`): stops 2–4 body, fibre grain = sparse
  adjacent-step dither, deckle/torn edges bite 1–2px irregularly; no pure
  white. Ink text/sigils in `ink`, never black #000.
- **Fire / embers** (`ember`, `amber`): the one place chroma runs hot and
  the ramp's +29° hue sweep does the work — model glow by stepping the
  ramp, never by alpha or blur.

## 16px humanoids: face, skin, hair

The settler head front face is **8×8**. Restraint is the craft; every added
pixel costs readability. The house construction (from `gen_settler.py` —
keep new variants consistent with it):

- **Layer separation**: skin base layer owns face *modelling* (brow light,
  socket shadow, nose, mouth); the face layer owns **only eye colour**; the
  hair layer owns hair + brows + beard. Never duplicate a feature across
  layers.
- **Eyes** (row y+3): 2px per eye — white at the outer column (x+1, x+6),
  iris at the inner (x+2, x+5). Inward-set irises give a forward gaze;
  1px-tall eyes only — 2px-tall eyes at 8×8 turn the settler into a doll.
  The eye row is the highest-contrast row of the face; nothing else on the
  face may exceed it.
- **Brow** (row y+2): hair ramp stop 1 ×1.05, over the eye columns. It is
  the expression carrier — flat = neutral; skip a pixel for asymmetry only
  on deliberate character variants.
- **Nose**: 1px, skin stop 1, centre columns, row y+4. No nostrils.
- **Mouth** (row y+5): 2px wide, centre, `shade(skin[1], 0.9)` — one value
  darker, never red, never outlined, never smiling (a 16px smile grimaces).
- **Face modelling**: forehead rows catch light (stop+1), jaw row slightly
  darker; vertical gradient only — no cheek circles (pillow face). Optional
  single warm blush pixel per cheek on child/innkeeper variants.
- **Skin elsewhere**: hands from stop 3 with a stop-1 knuckle row; skin
  shadows warm, never gray (see palette law #4).
- **Hair**: **ribbon clumps, not strands** — vertical runs of stops 1–2–3
  following flow (down from the crown, forward at the fringe). Glints: stop
  3 pixels on a modulus of 7–9 (`strand_idx`) so they never align into
  rows. A darkened (×0.82) part line breaks the top-face mass. Beards keep
  the mouth row visible. Side hair connects to back rows or ends cleanly —
  no floating tufts.
- **Trade telling** (`PROFESSION_OUTFITS`): every profession differs from
  every other by ≥2 of {hue family (different ramp or ΔH ≥ 30°), headgear
  silhouette, part combination (apron / bracers / satchel / helm)}. Eleven
  trades in one brown apron is eleven settlers you cannot tell apart across
  a square. Silhouette beats colour: hood+satchel reads "scholar" first.

## Tiling & Minecraft-specific rules

- **Tile test**: every block texture must be reviewed tiled 3×3 (PIL paste
  loop or `montage`). Two failure classes: *grid errors* — light/dark bands
  near borders forming gridlines when tiled (noise amplitude within 1px of
  a border must match the interior; no directional highlight along a
  border); *pattern errors* — one distinctive cluster (a dark blob, a knot)
  that repeats into a visible motif at distance.
- **Seamless materials** wrap their noise coordinates (16-periodic, like
  `plaque_brass`); materials for multi-element block models must read
  through **any UV window** — micro-relief everywhere, macro gradient
  nowhere. Exception (learned the hard way): elements that all face the
  same way in-world (the four plaque corner brackets) need top-left-key
  brightness **baked per quadrant**, or every corner renders flat gray.
- **Mixels forbidden**: one texture, one texel grid. If 16×16 lacks room
  for a detail, the detail is wrong — do not paint at 32 and shrink.
- **Jaggies**: straight and diagonal edges keep consistent step lengths
  (1,1,1… or 2,2,2…, never 1,2,1,3).
- Entity sheets follow `FACE_LIGHT` (top/front brighter than bottom/back) —
  the entity-space equivalent of vanilla's rule.

## Critique checklist (run before claiming art is done)

Measurable from the PNG (script or eyeball on the actual file):
1. **Ramp audit**: every opaque pixel's colour derives from a texlib ramp ×
   a sanctioned factor. Foreign RGB literals = defect.
2. **Banding scan**: adjacent rows/columns with identical run patterns in
   consecutive ramp steps, ≥4px — flag and break up.
3. **Centroid light test** per form: mean(stop-4 px) up-left of
   mean(stop-0 px). Fails ⇒ pillow shading or inverted light.
4. **Orphan count**: 8-connected singleton pixels that are not on the glint
   whitelist (rivets, hair glints, eye whites) = defect.
5. **Grayscale trade test**: composite adjacent trades' turnarounds, convert
   to L; each pair differs ≥15 L-points over some major region OR differs in
   silhouette. Then downscale the sheet to 25% (NEAREST) — if you cannot
   name each trade in the thumbnail, fail.
6. **Tile 3×3** every block texture; check gridlines and repeated motifs.
7. **Colour count**: >2 ramps + 2 accents on one 16×16 = simplify.
8. **Silhouette test** for items: flood the sprite black; still nameable at
   hotbar size or fail.

Measurable from generator code:
9. Explicit int seeds; run twice, `sha1sum` identical.
10. Distinct rng draw sequence per face/side (no mirrored noise).
11. Grain axis parameter equals board/limb axis at every call site.
12. `shade()` factors outside 0.88–1.12 only for FACE_LIGHT/documented
    macro light; a comment states which light each factor encodes.
13. New colours added to `texlib.PALETTES` as full dark→light 5-tuples that
    pass palette law 1–3 — never local constants.

## Failure smells specific to generated textures

- **Flat single-hue shading**: a form modelled entirely by `shade(base, f)`
  at varying f — uniform RGB multiplication, zero hue movement. The PNG
  tell: many colours sharing one exact hue. Fix: step the ramp.
- **Mirrored noise**: left/right faces byte-identical because the same
  seeded sequence painted both, or noise keyed on `abs(i-centre)`. Organic
  material is never symmetric.
- **Gradient banding**: `v_grad`/`h_grad` producing rows of constant value
  — horizontal stripes. Keep `v_grad ≤ 0.15` and let weave noise break rows.
- **Outline-everywhere**: `outline_rect` reflexively around every part.
  Outlines are for transparent-background sprites only.
- **TV static**: per-pixel independent flips with no cluster runs.
- **Uniform detail density**: identical noise across a whole garment — real
  texture concentrates (folds, hems, worn spots) and leaves rest areas.
- **Ramp inversion**: highlight painted with a *lower* index than its
  surroundings — always index-check, dark→light is the law.
- **Glint spam**: crown/glint pixels denser than 1 per 8×8 region.
- **Loop-index patterning**: `(i*7 + j*13) % 11`-style texture is fine until
  the modulus aliases with the face width into diagonals — check the PNG.

## Keyframe animation

Animations live in `client/model/SettlerAnimations.java` as vanilla
`AnimationDefinition`s, played from `SettlerModel.setupAnim` off the synced
`SettlerActivity`. **Standing product rule: every task has its own bespoke
clip** — reuse is a placeholder. Reference bar is TekTopia; beat it.

- Bone names match `SettlerModel` parts exactly (`root`, `torso`, `head`,
  `right_arm`, `left_arm`, `right_leg`, `left_leg`, `cloak`).
- Looping clips close: first and last keyframe of every channel equal.
- `CATMULLROM` for flow; `LINEAR` for impact frames (a strike snaps).
- Amplitudes stay in vanilla range; distinct silhouette and rhythm per
  activity — recognisable across the village with no nameplate.
- **Sound-sync contract**: impact keyframe timestamp = the tick the goal
  plays its sound (e.g. CHOP strikes at t=0.55s of a 1s loop; the goal
  plays the thock at tick 11 of 20). State the contract in a comment above
  the clip; assert it in `anim_check.py`.

```bash
python3 tools/anim_check.py
tools/hearthstead-qa animation
```

## Verification is not optional

All art changes route through the QA controller (`hearthstead-qa` skill,
`qa/PROTOCOL.md`): `validate`, `animation`, `client` (real boot under Xvfb +
screenshot), `visual` (**a UI/art claim without an actually-inspected
screenshot is BLOCKED, never PASS**). Previews are evidence: regenerate
`preview_settler.py` turnarounds after any skin change and *look at them* —
run the critique checklist above on what you see.

## Adding a new profession (worked example)

1. `gen_settler.py`: add `PROFESSION_OUTFITS` entry — check the trade-telling
   rule (≥2 distinguishers vs every existing trade) before choosing parts.
2. Regenerate skins; run checklist items 1–5 on the turnaround.
3. `gen_blocks_items.py`: writ/tool art (silhouette test, sel-out rule).
4. `SettlerAnimations.java`: bespoke clip(s) with sound-sync contract; wire
   in `SettlerModel.setupAnim`; `gen_sounds.py` work sounds.
5. `en_us.json` (+ `nb_no.json` parity); `validate_assets.py` +
   `anim_check.py` green; full QA run.
