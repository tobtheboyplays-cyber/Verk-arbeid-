# --- INPUT CLASS 3/4: click. Aim down and right-click to place the hearth,
# then have the server itself confirm the block landed (AC-2). The input
# class under test here is the BUTTON PRESS, proven live to be 100%
# reliable (it reliably broke a known test block) independent of the mouse
# camera-look reliability problem documented in the `move`/`look` handlers —
# so the aim itself is set deterministically via console `tp <player> ~ ~ ~
# <yaw> <pitch>` rather than through synthetic mouse motion, isolating this
# check to what it actually tests. Exactly where the crosshair then lands is
# still not hand-derived: count hearth blocks in a generous reach-distance
# box around the player's own position — deterministic and non-destructive
# (fill replaces hearth with itself, a no-op where it matches).
# NOT a bare `tp $PLAYER ~ ~ ~ ...` — a console-issued command's `~`
# resolves against the CONSOLE's own position context, not the target
# entity's (proven live: it teleported the player to the console's default
# origin instead of keeping their position). `execute at` anchors the
# position context to the player first. Pitch 45 (not steeper) is
# deliberate: proven live that 60 places the target too close to the
# player's own feet/hitbox for the placement to succeed; 45 reliably lands
# a few blocks out on open ground and actually founds the settlement.
scmd execute at $PLAYER run tp $PLAYER ~ ~ ~ 0 45

# else. Two independent reasons, both proven live: (1) that hearth's
# settlement can by now have starved and disbanded ("the hearth has gone

# blocks around its OWN hearth, while a new settlement refuses to found

# for the old one to cover it, and PlaqueBlockEntity.link() reports that

# new hearth is placed). 300 blocks clears both radii with a wide margin

scmd execute at $PLAYER run forceload add ~-8 ~-8

scmd execute at $PLAYER run tp $PLAYER ~ ~ ~ 0 0
